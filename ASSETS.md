# Assets

Every file under `assets/` ships with the game: Godot imports it and packs it into the export. The exceptions are `assets/source/`, which has a `.gdignore` so Godot neither imports nor exports it, and the `.import` files Godot writes next to each asset. Each shipped file is listed below with its source, author, licence and use.

`test_assets_listed` in `tests/test_assets.gd` fails if a shipped file under `assets/` has no row here, if a row names a file that does not exist, or if a row's licence is not `CC0-1.0`, `OFL-1.1` or `Own work`. Add the row in the same change as the file.

## GodotSteam (`addons/godotsteam/`), shipped in the Steam builds only

The Steam builds (the export presets `Linux Steam` and `Windows Steam`) ship GodotSteam, the GDExtension that lets the game talk to Steam (Steam Input, docs/STEAM_INPUT.md). The builds without Steam (`Linux`, `Windows Desktop`) leave the folder out with their `exclude_filter`, and the game runs without it.

## Not shipped

- `assets/source/grafxkid-td-racing-assets.png`: the original sheet (CC0, GrafxKid), committed so the slicer runs offline. `tools/fetch_assets.py` downloads it again and checks its pinned SHA-256. It is input to the slicer only, and `assets/source/.gdignore` keeps it out of the Godot import and export.
- Parts of the sheet left out of the atlas: the sheet labels, the two example track layouts, the HUD mock-up (only its fuel gauge is cut out), the player avatars, a few sprites that could not be identified, and pixel-identical duplicates. `python3 tools/slice-sheet.py` lists each one with its position and the reason.

## Rebuilding

```bash
python3 tools/fetch_assets.py     # download the sheet into assets/source/ and check its SHA-256
python3 tools/slice-sheet.py      # needs Pillow; writes assets/sprites.png and assets/sprites.json
# The font, from the npm registry (no package.json needed):
npm pack @fontsource/press-start-2p@5.3.0
tar -xzf fontsource-press-start-2p-5.3.0.tgz package/files/press-start-2p-latin-400-normal.woff2 package/LICENSE
cp package/files/press-start-2p-latin-400-normal.woff2 assets/font/
cp package/LICENSE assets/font/OFL.txt
```

`fetch_assets.py` uses only the Python standard library and reads `HTTPS_PROXY` from the environment. Behind a proxy with its own certificate authority, set `SSL_CERT_FILE` to that CA bundle.

The font's `.import` file is committed: it imports the font with `antialiasing=0`, `hinting=0` and `subpixel_positioning=0`, so the pixel font stays sharp (docs/GODOT_PLAN.md §2).

## Art drawn in code

The sheet has no truck. Any sprite it does not provide is drawn in code as a pixel grid in the project's own palette (`docs/ART_PLAN.md` §2). That art is the project's own work. If it is ever exported as a file under `assets/`, add a row above with the licence `Own work`.

What is drawn in code, and why (colours are picked from the sheet so it matches). The paths below are in the Phaser version (commit `0a0841f`); the Godot port draws the same grids in `scripts/view/` (docs/GODOT_PLAN.md §5):

| Art | Where | Why |
|---|---|---|
| Truck: green cab, white container, 10×20 plus a 1 px shadow, drawn at 3× (the 30×60 hitbox) | `TRUCK` in `src/render/pixelArt.ts` | The sheet has no truck |
| Oil puddle: 10×6, drawn at 4× (the 40×24 hitbox) | `OIL_PUDDLE` in `src/render/pixelArt.ts` | The sheet's `oil_spill` is 6×6, too small and the wrong shape for the hitbox |
| Lane dashes between the three lanes | `drawBackdrop` in `src/render/draw.ts` | The sheet only has a two-lane centre line |
| Goal and fuel gauges, panels and the START button | `src/render/draw.ts`, `src/scenes/` | The sheet's `hud_fuel_gauge` has its fill baked in |

The rainbow fuel car is the sheet's `car_police`, tinted with a hue cycle. That is a tint, not new art.
